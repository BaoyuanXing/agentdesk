# AgentDesk

AgentDesk is a small resident desktop agent for local workflows. It sits like a compact desktop icon, expands into a CLI-style agent console, and uses a local runtime to create runs, persist state, execute jobs, and write artifacts to disk.

The app is intentionally web-first so it can move quickly, while keeping a shape that can later be wrapped with Tauri for local files, shell tools, notifications, and OS-level integrations.

## What is here

- Compact desktop agent icon that expands into a terminal-like console.
- Local runtime API for creating and monitoring runs.
- Real persisted state under `.agentdesk/`.
- Markdown artifacts generated by completed runs.
- Built-in slash commands for `/audit`, `/typecheck`, and `/codex`.
- Vite + React + TypeScript developer setup.
- Browser-only implementation today, with room for a future `src-tauri` shell.

## Getting started

```bash
npm install
npm run dev:real
```

Then open the local URL Vite prints, usually `http://localhost:5173`.

`dev:real` starts both pieces:

- AgentDesk runtime: `http://127.0.0.1:8787`
- Vite UI: `http://127.0.0.1:5173`

Click the `AD` agent icon to open the console. Type an objective or use a slash command:

```text
/audit inspect this repository
/typecheck
/codex review this repository and suggest next steps
```

Completed runs create markdown reports in `.agentdesk/artifacts/`, and the console links to the latest artifact.

## Scripts

```bash
npm run dev        # start the development server
npm run dev:real   # start the local runtime and Vite UI together
npm run server     # start only the AgentDesk runtime API
npm run build      # type-check and build production assets
npm run preview    # preview the production build
npm run typecheck  # run TypeScript only
```

## Product direction

AgentDesk should become a lightweight desktop presence that can expand into an agent terminal whenever you need it. The core metaphor is not a dashboard; it is a small local agent sitting on your desktop that can be opened, given a task, watched, and collapsed again.

Likely next steps:

- Add a true always-on desktop wrapper with Tauri.
- Add draggable placement and persisted collapsed/expanded position.
- Introduce an app registry for agent tools such as browser, files, terminal, docs, and review.
- Add an approval queue for file-changing runners.
- Harden the Codex runner around authentication, permission profiles, and artifact capture.
- Add a Tauri shell when local capabilities are needed.
- Model artifacts as first-class files that can be opened, compared, exported, and handed between agents.

## Tauri path

The current project can stay as the frontend package. A future Tauri integration can add:

```text
src-tauri/
  Cargo.toml
  tauri.conf.json
  src/
```

The frontend can continue to run through Vite, while Tauri provides secure local capabilities through explicit commands.
